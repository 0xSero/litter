# Litter 2.1.1 candidate validation

## Source and behavior

- Shared SSH setup no longer executes user profile files or a Fish login shell.
  It preserves inherited PATH and adds existing common tool/Nix directories.
- Codex thread start/resume/fork disables login-shell tools and shell snapshots
  through shared Rust request configuration on both platforms.
- Kittylitter 0.3.8 pins Alleycat `7710c7a`, one commit on the previous production
  `5dd425f` lineage. Interactive login-shell environment capture is off by default.
- Thread reconciliation reads one thread rather than cloning every server,
  session and terminal tail. Android home sorting depends only on server and
  session-summary changes rather than every app snapshot update.
- Android Ghostty uses epoll directly to avoid fatal io_uring probes (#354).
- Model-list timing logs now identify runtime, elapsed milliseconds and success.
  They contain no prompt, credential or model response content.

## Verified locally

- Shared Rust library: 809 passed, 0 failed, 3 ignored (including manual benchmark).
- Alleycat bridge-core: 91 tests passed across unit/integration suites. The new
  subprocess regression fails with the old interactive-shell default restored.
- SSH shell templates: bash syntax and shellcheck passed.
- Synthetic SSH setup fixture, ten calls and six 30-ms startup hooks per call:
  median 261.30 ms before, 5.83 ms after; hook executions 60 before, 0 after.
  These are controlled setup costs, not real network latency.
- Debug snapshot benchmark, 1000 cached threads and 200 reads: whole snapshot
  198528 microseconds; scoped thread 213 microseconds. This measures clone work,
  not whole-app frame rate or end-to-end latency.
- Xcode project regenerated from project.yml.
- Swift and Kotlin bindings regenerated successfully; Slingshot tests: 14 passed.
- iOS simulator build 210010003 installed and launched. XCTest: 251 unit and
  10 UI tests passed. Android JVM tests: 58 passed across 15 suites.
- This Mac's installed Kittylitter upgraded from 0.3.6 to 0.3.8. Live Codex
  E2E now passes all 14 checks: availability, streaming, desktop reads, persisted
  threads, tool/file ordering, reconnect, compaction and post-compaction hydration.
  Commands in the trace use a non-login shell. Earlier intermittent thread-list
  timeouts remain a reliability concern; one green run does not erase them.
  The harness now resolves its output directory absolutely so a separate proof
  working directory does not produce false missing-file failures.
- Six subsequent fresh Iroh probes returned thread lists successfully: 10 rows
  in 86–136 ms and default 25 rows in 422–522 ms after request transmission.
  These exclude initial dialing and do not measure mobile tap-to-content time.
- XCTest projection measurements: 200 turns/1000 items built in a median
  1.335 ms; a batch of 100 stream-cache updates over 1000 items took 2.345 ms.
  These are projection costs, not scrolling frame-rate measurements.
- Local Studio transport/reconnect and existing session reads passed, but the
  Mac's local Pi catalog contains no `local-studio` provider while its default
  selects that provider. The model catalog is empty and turns fail with a
  connection error; this path has not passed end-to-end acceptance.

## Remaining acceptance

Signed mobile builds, installed mobile networking,
Android Terminal open/input/close/reopen, scrolling and streaming measurements,
signed artifact provenance, and App Store/Play approval remain required.
No upload, draft or review submission counts as an accepted release.

## GitHub review decisions

- PR #351 closed without merging: overlapping shared cursor writers, refresh
  callback ending before completion, nonvirtualized growing iOS home rows, and
  removal of Android pinch handling. Existing conversation pagination remains.
- Feature proposals #236 (jcode), #207 (Local Studio voice provider), and #146
  (signed daemon tags) closed as not planned for this stabilization direction.
  Those capabilities are not claimed implemented.
- #258: Android/daemon release channels, artifacts and failure diagnostics are
  now linked in the Android release guide and Kittylitter README.
- #354 remains open until installed Android Terminal acceptance.
- #305, #257, #206, #189, #185 and #66 remain under review; their unresolved
  requirements have not been silently marked complete.
- #305: a fresh iOS 26 XCTest probe finds and taps the accessible New message
  and Settings controls. The empty composer did not collapse after a background
  tap or a dashboard downward swipe with the simulator keyboard offscreen.
  This is not evidence that physical-device keyboard dismissal or edge-back
  gestures work; the navigation issue remains open.
